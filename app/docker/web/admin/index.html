🧩 文件名解析

    

      按你曲库文件真实的命名习惯填写解析格式：用"歌手""歌名"（或"歌曲名"）代表这两个字段；
      语种、风格可以直接写当前预设里的取值（如"国语""流行"）当占位，不用记抽象字段名；
      其余文字、分隔符、括号照抄一遍，系统靠它们定位每个字段的位置，最终结果里会自动
      去掉括号这类无用信息。

      例如文件实际命名是「周杰伦-晴天(国语-流行).mp4」，解析格式就填：歌手-歌名(国语-流行)

🧹 一键清洗

    

      维护一份"忽略词"列表（比如画质/平台版本标记：1080p、抖音版、live），
      命中就整体从歌名里摘掉，只留下干净的歌曲名；同时只要歌名里任意位置（不限开头/结尾/某个
      固定分隔符位置）命中当前语种/风格预设列表里的取值（如"国语""流行"），
      也会顺带识别出来、从歌名里摘出，一起放进预览里对照确认，勾选或全部确认后才批量写回。

📂 曲库源设置

    
docker-compose.yml 只固定挂载两个通用目录：/mv(本地曲库)、/mv-net(网络/网盘曲库)。把 host 上的文件夹（本地目录，或用 fnOS 网盘挂载/rclone/alist 等工具挂出来的网盘目录）对应放进这两个共享目录后，在下面浏览并选择要作为曲库来源的子文件夹即可——保存后立即生效，不需要重建容器。

网盘本地缓存调优

      

        
        MB
      

      
网络路径的曲目第一次被探测/播放时会先完整拷贝到本地磁盘，缓存总量超过这个上限时按最久未访问优先清理

      

        
        天
      

      
超过这么多天没被访问的本地缓存会被自动清理，源网盘文件不受影响，下次点唱会重新缓存

      

        
        个
      

      
同时最多拷贝几个文件到本地；网盘场景下并发太多反而互相抢带宽，一般保持默认(2)即可
