# 项目路线图

> momo-ktv 项目的长期发展规划，按优先级和时间线排列。

---

## 🎯 愿景

打造最易用的家庭 KTV 系统：**任何设备、任何来源、任何歌曲**，都能像 KTV 包厢一样流畅点歌演唱。

---

## 📅 时间线

### 2026 Q3（当前）：网盘曲库集成
- **核心目标**：摆脱本地存储限制，网盘即曲库
- **关键功能**：
  - 内置扫码添加 115 网盘 / 阿里云盘
  - 指定网盘文件夹自动扫描入库
  - 直链串流播放，不占本地空间
  - 本地缓存 + LRU 淘汰
  - 人声分离文件云同步（一次分离，到处使用）
- **交付物**：网盘管理后台、115/阿里云盘驱动、扫描器、串流代理、缓存系统

### 2026 Q4：全平台客户端
- **核心目标**：覆盖所有常用设备，体验一致
- **关键功能**：
  - iOS 原生客户端（iPhone/iPad）
  - 安卓手机原生客户端
  - 微信小程序点歌（免安装）
  - 客户端统一架构（共享核心逻辑）
- **交付物**：iOS App、Android App、微信小程序

### 2027 Q1：AI 深度增强
- **核心目标**：AI 不仅生成歌词，还要理解音乐
- **关键功能**：
  - AI 自动评分（音准、节奏、表现力）
  - AI 修音（实时音高修正，像 Auto-Tune）
  - AI 和声（自动生成和声伴唱）
  - AI 推荐（根据演唱历史推荐歌曲）
  - 语音点歌（"我要唱周杰伦的晴天"）
- **交付物**：评分系统、修音引擎、和声生成、推荐算法

### 2027 Q2：社交与娱乐
- **核心目标**：从单人 KTV 到多人娱乐
- **关键功能**：
  - 好友系统（添加好友、查看动态）
  - 歌单分享（创建/分享/收藏歌单）
  - 合唱功能（异地实时合唱）
  - 擂台赛（打分排名、 weekly 榜单）
  - 作品录制与分享（录唱后生成视频）
- **交付物**：社交模块、合唱引擎、录制系统

### 2027 Q3+：生态扩展
- **核心目标**：成为家庭娱乐中心
- **关键功能**：
  - 智能家居联动（灯光、音响、投影）
  - 第三方插件系统（开发者可扩展）
  - 开放 API（对接其他家庭娱乐系统）
  - 多房间同步（客厅+卧室同时播放）
  - 云端曲库（官方维护的正版曲库订阅）
- **交付物**：插件系统、开放平台、多房间方案

## 🏗️ 技术架构演进

### 当前架构
```
本地文件 → 扫描入库 → HLS转码 → 客户端播放
         ↘ AI分离 → 本地缓存 → DUAL双轨
```

### 网盘集成后（Q3）
```
本地文件 + 网盘文件 → 统一扫描入库 → HLS转码 → 客户端播放
                    ↘ AI分离 → 网盘同步 → 多设备共享
```

### 全平台后（Q4）
```
云服务端 → 统一API → iOS / Android / tvOS / AndroidTV / Web / 小程序
```

### AI 增强后（Q1 2027）
```
音频流 → AI实时处理（修音/和声/评分） → 输出
       ↘ AI理解（推荐/语音点歌）
```

## ⚠️ 风险与挑战

| 风险 | 影响 | 应对策略 |
|------|------|----------|
| 网盘 API 变化 | 网盘功能失效 | 驱动层抽象，变化只改驱动 |
| 版权问题 | 云端曲库无法推进 | 只做工具，不提供内容；用户自备曲库 |
| AI 算力成本 | 实时修音/评分成本高 | 本地推理优先，云端按需付费 |
| 多端维护成本 | 平台越多维护越重 | 共享核心逻辑，原生壳 + Web 内容 |
| 网络带宽 | 网盘串流依赖带宽 | 本地缓存 + 预加载 + 码率自适应 |
